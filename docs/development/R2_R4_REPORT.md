## 关键行为与兼容变化

- 计划、实际片段和事件独立存储。睡眠计划到期只发出评估触发，不创建实际睡眠；活动检查点不自动宣称完成。
- 正常自主入睡只接受持久化且与当前依据一致的模型候选。5–1080 分钟、从初次开始最长 1080 分钟、最多两次延长、新会话 5 分钟冷却；兼容观察仍按旧窗口截止。临时中断不改最后完整起床，不补足中断分钟。
- 恢复错过的睡眠截止时，事件 occurred_at 是原逻辑截止，recorded_at 是当前记录时间；社交有效期不因此延后。清醒活动停机区间显示未知，不补造活动，也不用于习惯或连续睡眠债覆盖。
- 当前 Schema 4 包含 28 表、4 个显式索引、21 个触发器。001 不变，002–004 显式升级；普通打开不升级，拒绝未知/更高版本/漂移。表重建在独占迁移事务中完成并校验全部外键；无自动降级。
- 新逻辑 API 使用 v1 封套，旧 get_current_activity 仍保留裸 dict。公开参数无法开启 private_details 或指定 authorized 来源。新门面由可信适配器提供 scope/policy。
- 旧 Tool 的 delete 明确映射为取消并保留审计，complete 需要实际证据；update_schedule 产生待确认提议，不能直接确认约定。旧的周/月导出不会无提示写成同一天；需补明确日期映射。上述是新隔离门面的行为，R0 入口仍保持原服务。
- 离线导入把已消费 completed 的未来约定继续保护，不认作 fulfilled；只有时间点、歧义关联/坏 JSON/未知类型会保留待审。存在待审原行时阻止自主暂存 Runtime 启动。
- 估计/习惯/清理都可独立停用或不启动；保守清理只移除已验证摘要覆盖的模型候选正文。实际事实、会话、约定、迁移原行、命令/决策审计与事件不会随普通清理被删除。

## 未解决阻断与风险

1. **R0-06/08**：固定 Host/SDK 缺可信管理发送回执及按插件归属撤销频率的接口，且没有隔离真实 Runner。不能靠内部端口或模型输出补造这些能力，不能宣布 R0 正式通过。
2. **R1-05/07 和 R2-07 宿主接线**：默认入口仍读写 R0；新 API/Tool 是逻辑门面，不是已发布的 SDK API。实际模型路由、GoalManager 停写、API/注入投影与激活清单必须在真实隔离 Runner 中实现并验收后才能解除接管门禁。
3. **R3 契约**：本机 Owner Auth v2.1.0 / HEAD `155df1ae0dbde4a8690efb2a082ed9c9c6ede40d` 是身份提示注入，没有导出的身份 API；统一策略、社交、记忆也没有已核实契约。见 `evidence/r3-contract-matrix.json`。未修改这些项目来造接口。
4. **R2-08 / R4-06**：24 小时与 7 天实机观察均未运行。30 天替身回放不能证明真实模型质量、权限配置、平台回执、跨插件 Hook 或长期宿主性能。
5. **保守范围**：周/月旧导出逐日映射、真实迁移待审消歧、原始事实物理压缩归档尚未提供自动路径；当前显式拒绝或保留原记录。全量结构/聚合校验优先保证正确性，规模更大时需测量并优化，不能称无限期运行已经验收。
6. 外部投递至少一次；消费者必须用 event_id 持久去重，网络没有 exactly-once 保证。无消费者、失败与过期保留诊断，不阻塞生活状态事务。
