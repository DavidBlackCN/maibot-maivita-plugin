## 1. 开发约束和阶段定义

本计划最初为文档交付；R0 离线实现已交付，但尚未正式通过。后续授权已扩展为依次完成剩余 R1 依赖及 R2–R4 开发，可与 R0 实机工作并行。使用隔离合成库和内部契约替身，不授权修改宿主、生产迁移、切换或部署。工程交付与正式验收分别记录。

最新授权转入 **I0：宿主集成准备与隔离 Runner 验证**。停止新增生活模拟特性；保留现有 R1–R4 核心、R0 兼容层与正式门禁。允许在临时空实例运行固定公开 Host 源码的原始 Runner 与运行时模块，配合明确的业务边界替身验证契约。未经确认不修改 Host/其他插件源码，不读取生产数据，不同时启动新旧调度器。方案和人工清单见 [I0_INTEGRATION_PLAN.md](I0_INTEGRATION_PLAN.md)，结果见 [I0_REPORT.md](I0_REPORT.md)。

后续明确授权进入 **I1：首个可安装开发测试版**，允许在 `D:\Dev\maimai-plugin\maibot` 安装官方最新完整 Host，使用专用合成实例和用户提供的测试模型，并已同意本次隔离实例的 Host EULA/隐私条款、关闭遥测。版本固定为官方 v1.3.12 / `5c7637e`、SDK 2.15.0，不跟随浮动 main。新增生活模拟特性继续冻结，正式 R0–R4 和生产门禁不变；H01–H03 暂缺时采用关闭/拒绝，H04 在本插件完成。详见 [I1_REPORT.md](I1_REPORT.md)。

开发时首先读取适用的 AGENTS.md、工作区状态和已有文件。不覆盖用户改动，不把整个旧目录连同 `.git`、运行数据、日志、凭据复制到新项目。若需建立新代码基线，应保留现有这五份文档及旧项目版权/许可证；在新目录有选择地引入源码与测试，旧目录保持只读。Git 提交、推送、生产部署和实际迁移只有在相应任务明确授权时执行。

设计标识统一：新插件 ID 为 `davidblackcn.maibot-maivita-plugin`，新库 `maivita.db`，初版配置结构版本 `1`，角色默认 `default`。发布版本、Schema 版本和 R 阶段独立。

## 2. 全阶段完成标准

- 需求中的 INV-01 至 INV-12 在适用阶段成立，偏差有明确记录。
- 变更有正常路径、重要失败路径和恢复路径测试；不靠与实现同构的测试证明正确。
- 所有时间测试使用可控 Clock，关键并发/迁移测试使用临时真实 SQLite。
- 模型以固定响应、延迟响应、非法响应和不确定超时替身测试；实机试运行另外记录。
- 不读取真实用户聊天或生产数据库作为可公开测试 fixture，样本必须脱敏。
- 提交状态、计划、会话与 outbox 的原子性有故障注入证明。
- 新 API、旧 API、配置示例与文档一致；明确“已实现”“尚未实现”“受外部依赖阻塞”。
- 每阶段报告包含修改范围、测试结果、人工验收、迁移/回滚影响、已知限制和下一阶段入口。
- 没有生成器、清理循环、Hook 或频率调整在卸载/热重载后泄漏。

## 5. R2：混合规划与自主睡眠

### 5.1 目标与范围

这是核心行为变更。建立长周期方向、每日计划、即时决策；允许自由时间；把实际入睡核实与预期时长交给 LLM，把计时和一致性留给程序。

本阶段不等待完整外部策略层，使用范围受限的 IdentityPort/PolicyPort 适配和可信本地管理员配置。不会在 MaiVita 内实现通用 Owner Auth。

### 5.2 任务
