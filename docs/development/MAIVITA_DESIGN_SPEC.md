## 2. 目标、边界与首版范围

### 2.1 核心目标

1. 一名角色在一个宿主实例内只有一份权威生活状态，所有聊天流观察同一条生活时间轴。
2. 长周期规划、每日计划和事件驱动即时决策相互配合，不强制填满 24 小时。
3. LLM 自主决定是否入睡、何时入睡和睡多久；作息偏好只提供参考。
4. 程序负责时间合法性、状态一致性、权限校验、异常保护、确定性计时和持久化。
5. 计划、实际经历、主观估计和社交上下文清晰分离，允许可靠重启、迁移与回退。
6. 产生生活事件供外部系统使用，逐步解除与主动发言、频率和身份系统的耦合。

### 2.2 分工

| 系统 | 负责 | 不负责 |
|---|---|---|
| MaiVita | 生活事实、规划、活动、睡眠、习惯、生活事件 | 统一人格、所有消息发送决策、身份认证、关系经营 |
| Owner Auth | 可信身份、身份声明及可验证来源 | 单独决定某次唤醒或改计划是否允许 |
| 统一策略层 | 结合身份、生活状态、会话规则裁定操作/回复/主动行为 | 修改 MaiVita 数据库、生成生活事实 |
| 主动社交系统 | 选择交流对象、场景、内容及发送时机 | 直接修改睡眠或实际活动 |
| 宿主记忆系统 | 通用记忆存储和检索 | 成为另一份权威当前生活状态 |

Owner Auth 与策略层未就绪时必须使用可替换适配器；不在 MaiVita 内另造全局权限、社交或情绪系统。

### 2.3 首版与非目标

R0–R2 建立核心试运行版本，R3 完成框架集成，R4 完成首版生活表现。各阶段验收独立，不能把 R4 全部完成作为开始试运行的前提。

首版包括 Energy、Fatigue、Stress、Sleep Debt 四个轻量维度；生活偏好、目标、约定、活动历史；有限习惯演化和最多两个副活动。首版不引入完整情绪引擎、经济与资产模拟、疾病/营养/器官等健康模拟、复杂生理学、完整社会关系模拟或多角色世界。外部情绪摘要可以作为有来源、有时效的只读输入。

不把模型生成的生活描述包装成已实际调用工具完成的现实行为。例如“读书”是角色生活活动，不能因此声称已读取本地文件或访问网站。

## 3. 不可破坏的运行约束

| ID | 约束 | 验证方式 |
|---|---|---|
| INV-01 | 每个 `character_id` 只有一个权威状态；`chat_id` 不分裂生活实例 | 多聊天流一致性测试 |
| INV-02 | 任一时刻至多一个实际主活动、一个未结束睡眠会话 | 数据库约束、并发测试 |
| INV-03 | 计划不是事实；历史事实不被重规划覆盖 | 计划差异与历史不可变测试 |
| INV-04 | 正常自主模式的实际入睡及预期时长来自有效 LLM 决策 | 决策来源审计 |
| INV-05 | 所有写入经统一状态服务与版本检查，过期决策不得覆盖新状态 | 竞争和重试测试 |
| INV-06 | 事实状态、活动记录、计划修订和待发布事件在同一事务提交 | 断电/事务故障测试 |
| INV-07 | 普通群聊和普通 @ 不自动唤醒；身份、策略和生活变更分离 | 权限矩阵测试 |
| INV-08 | 已确认约定不得被模型静默删除、改时或视为已完成 | 约定保护测试 |
| INV-09 | 重启不得生成重复活动、重复醒来或重复对外副作用 | 恢复及消费去重测试 |
| INV-10 | 失败不清库、不重造历史、不让静默或重试无限延续 | 降级与保护测试 |
| INV-11 | 生活共享不等于聊天内容共享；跨流输出遵守可见范围 | 隐私隔离测试 |
| INV-12 | 任何时候只能有一个生效生活写入者；旧新插件不可并行调度 | 启动冲突及切换测试 |

R0/R1 的 `legacy_fixed` 模式为已记录的过渡例外，保留旧睡眠行为；INV-04 从 R2 自主模式启用时成立。兼容模式不得伪称已实现自主睡眠。

## 4. 三层生活信息

### 4.1 客观生活状态

由程序维护当前主活动、实际开始与结束时间、睡眠会话、最后完整起床时间、连续清醒时长、近期睡眠记录和当前计划版本。时间流逝可以计算持续时间，但不能据此声称学习任务或对外约定已完成。

初次迁移缺少实际记录时允许 `unknown` 和空时间，必须标明来源。旧日程里的“睡觉”不能自动转换成已经睡过的事实。

### 4.2 主观生活状态

| 字段 | 语义与首版单位 | 约束 |
|---|---|---|
| `energy` | 精力估计，0–100 | 不等同于 100 减疲劳 |
| `fatigue` | 疲劳估计，0–100 | 高值触发评估，不直接强制入睡 |
| `stress` | 压力估计，0–100 | 仅作节奏和活动选择输入 |
| `sleep_debt_minutes` | 滚动睡眠不足估计，分钟，非负 | 不作为医学指标或硬性作息命令 |

轻量程序推进与有界 LLM 调整共同形成估计。每次更新记录 `observed_at`、来源、模型/规则版本与简短原因。数值不可信或历史不足时带置信信息，不默认为精确事实。LLM 不能随意清零睡眠债或重写睡眠记录。

冷启动允许主观字段为 null，模型输入明确显示未知；若实现采用中性初值，建议前三项为 50，必须标记低置信度，不能叙述为真实观测。更新规则和变化率需集中配置并经过回放校准，首版不要求复杂生理曲线。

睡眠债首版建议按最近 7 个完整角色本地日计算：每日期望睡眠参考分钟数减去当天实际睡眠片段分钟数，负值按零处理后求和。跨午夜睡眠按日切分，中断不计入睡眠；不足 7 天则使用已知天数并标记覆盖不足。它是可重算派生值，不逐次累加以免重启重复计账；参数改变只重算估计，不改原始历史。参考睡眠需求是估计基准，不限制 LLM 选择时长。

### 4.3 生活记忆与习惯

- Preferences：人设、显式配置、自然语言偏好；明确硬约束与参考作息必须分字段。
- Habits：从多次实际经历缓慢归纳，记录证据、置信度和最近出现时间。
- History：实际活动、睡眠和变更历史，另存摘要。
- Commitments：已经接受的约定，有更强约束和来源范围。
- Goals / Life Direction：数天至数周的方向与目标，可自主调整进度。

“今晚八点一起游戏”是约定；“本月学会一首曲子”是长期目标。角色自己接受一般约定不等于允许任意人改管理员配置。

## 5. 混合规划

### 5.1 三个层级

| 层级 | 时间跨度 | 产物与触发 |
|---|---|---|
| Life Direction | 数天至数周 | 生活阶段、长期目标；低频总结或重要变化触发 |
| Daily Plan | 当天及接下来约一天 | 有限活动、约定和自由时间；每天一次或明显失效时重规划 |
| Immediate Intent | 当前至数小时 | 继续、结束、切换、休息、准备睡眠、入睡等决策；事件触发 |

Daily Plan 可以不完整。时间类型采用 `fixed`、`window`、`unscheduled`：确定时间使用完整时间戳；窗口活动使用起止窗口和偏好时长；未排时间项仅表示意图。进入实际活动时，必须物化为明确的开始时间及下一检查点。

固定时间也不自动表示已确认约定。约定必须有独立 `commitment_id` 和确认状态。睡眠计划项即使写了 23:30，也只触发入睡评估，不直接把角色设为睡眠。

### 5.2 增量重规划

触发包括活动接近结束、状态显著变化、新约定、时间冲突、目标变化、恢复启动和明确授权的外部请求。输出计划差异而非全表覆盖：新增、调整、取消待执行项，保留实际发生的记录。

程序校验时间、版本、权限、主活动冲突、约定冲突与来源；成功后原子提交差异、简短原因、前后版本与生活事件。普通计划项可自主调整；约定需要保留，或明确提出改约/取消请求。未经必要授权或对方确认，不把“想改约”当作“已经改约”。

冲突无法解决时保留约定、暂停冲突变更并输出结构化原因，允许规划其他不冲突活动。活动截止时间到了只表示应检查，不表示任务完成。

实际活动已确认结束而下一次模型决策失败时，可进入程序标记的 idle/rest 占位状态，记录 `source=fallback`，不宣称完成任务、不自动睡眠；仍在有效期内的活动则继续。后续评估有冷却和预算，不能不断重复相同失败请求。

### 5.3 调用控制

Strategic Planner 负责日计划、方向和习惯摘要；Immediate Decision 负责即时选择。可共用模型，但使用不同输出 Schema、上下文预算和超时设置。

Decision Coordinator 按角色合并近同时事件、去重、冷却、限预算，并在提交时检查状态/计划/配置版本。轻量兜底检查建议每 45 分钟，允许在 30–60 分钟范围调节；它主要做时间推进和异常检测，不等于调用 LLM。活动边界和唤醒使用独立到期调度，不能等待 45 分钟检查。

稳定状态没有新证据时不反复重规划。普通消息不逐条触发全局模型决策。超时结果不确定时不盲目重试；沿用旧版模型选择、限次重试和 Generation Coordinator 的有效经验。

## 6. 自主睡眠

### 6.1 两次决策与会话

1. 规划准备睡觉：例如 22:00 决定 23:30 左右休息，只建立意图。
2. 临近该时间重新评估：LLM 根据状态、约定和允许使用的事件摘要决定现在睡、推迟或继续活动，并给出预期睡眠分钟数。
3. 程序验证并创建 `SleepSession`，记录真实入睡时间，计算 `expected_wake_at`；结束或中断原主活动。
4. 睡眠期间由本地调度器推进，到期正常醒来无需调用模型。起床后才按需重新规划。

作息偏好、疲劳、压力、睡眠债和明日约定是模型输入。偏离偏好不是校验错误；负时长、非法时间、超过保护上限和未解决约定冲突才是拒绝原因。

### 6.2 状态与转换

| `sleep_phase` | 含义 | 是否有未结束 SleepSession |
|---|---|---|
| `awake` | 正常清醒 | 否 |
| `winding_down` | 准备睡觉，仍可改变主意 | 否 |
| `sleeping` | 正式睡眠，默认静默 | 是，status=`active` |
| `temporarily_awake` | 一次睡眠中的有限中断 | 是，status=`interrupted` |
| `waking` | 会话已结束，正在恢复清醒活动 | 否 |

`winding_down → awake` 允许取消休息意图；`sleeping → temporarily_awake → sleeping` 复用同一睡眠会话；结束会话进入 `waking → awake`。中断期间不计睡眠分钟数。到期醒来或保护唤醒必须退出静默状态，不能卡在 `waking` 永久等待 LLM。

一次临时唤醒不是新的完整起床：不重置“最后完整起床时间”；连续清醒时长应按清醒片段计算，完整会话及片段分别保留。

### 6.3 时长、延长和异常保护

正常时长由 LLM 提出，程序使用统一 Clock 以提交时刻计算结束时间。首版建议工程保护值：单次预期睡眠 5–1080 分钟；整个会话从首次入睡起最长 1080 分钟；最多延长 2 次；正常重新入睡冷却 5 分钟。这些是防坏数据和状态震荡的边界，不是人类健康建议，允许经回放测试调整。

上述数值用于 R2 autonomous 模式。R0/R1 的兼容睡眠按旧合法窗口截止，以保留原行为；迁移到自主模式前必须验证不存在超出新边界的开放会话，必要时等其结束后切换。

延长必须有明确事件/中断后的有效决策及原因，并在原会话上更新 deadline；不得每次检查随机推迟起床。上限从最初 `started_at` 计算，中断和延长不能重置上限。初版不默认添加随机起床偏差；后续变化必须可解释、可重放。

临时唤醒必须有 `interrupt_until`，建议 10 分钟且不得超过会话硬上限。到期仍无有效新决策时：原预计起床时间已到则结束会话，否则恢复睡眠至原预计时间；不自动补足中断分钟。正常恢复原会话不受“新建睡眠会话”的冷却限制。

保护可以拒绝非法决策、修复损坏状态或结束异常超长睡眠，并记录 `life.protection.triggered`。高疲劳、低精力或晚睡本身不授权程序强迫入睡。模型不可用时继续可信状态、推迟评估；不能暗中恢复固定窗口作为默认睡眠算法。

### 6.4 消息和唤醒

| 输入 | 默认处理 |
|---|---|
| 普通群消息、普通 @ | 留在所属社交上下文，不自动唤醒 |
| 私聊 | 默认不唤醒；可由明确策略开放 |
| 自称 Owner 的文字或 LLM 判断 | 不能作为授权凭据 |
| 可信 Owner 身份 + 策略允许的唤醒请求 | 提交有范围和有效期的唤醒命令 |
| 到期唤醒、会话上限保护 | 内部确定性状态转换，无需外部身份授权 |
| 管理命令回执 | 使用受限发送许可，不自动改变睡眠状态 |

MaiVita 提供 availability/静默建议，最终发送由统一策略层裁定。过渡 `before_send` 防护只能执行相同的生活状态限制，不长期覆盖其他插件结果。没有可信来源标记的普通文本不能伪装成管理回执。

## 7. 活动、打断与习惯

活动使用一级类别与自由名称。建议一级类别：`rest`、`study`、`work`、`entertainment`、`daily_life`、`social`、`travel`、`creative`、`other`。未知活动归 `other`，不因新名称拒绝生成。精力消耗、可中断性和专注等级使用有限标签，不引入复杂数值矩阵。

任何时刻至多一个主活动。R1/R2 先实现主活动与最小中断记录；R4 扩展恢复上下文和最多两个副活动。副活动不单独占据一条权威生活时间轴，不重复计算主要能量消耗；睡眠和高度专注场景拒绝不合理并行。

被打断的活动保存原因和恢复线索；恢复是新实际片段，可关联旧活动，不把中断期间伪装成持续执行。是否完成长期目标由完成证据决定，不能以计时结束直接推定。

R4 的习惯演化使用近期真实记录低频归纳。建议每周最多一次自动总结、至少 3 个不同日期的支持证据才提升为稳定候选；保存来源、置信度、衰减时间和数量上限。不得覆盖明确人设约束或管理员偏好。一次熬夜不足以形成长期习惯。

## 8. 共享状态与上下文隔离

默认 `character_id=default` 表示本宿主唯一角色，未来可扩展多角色但首版不实现多角色协调。聊天流只决定请求来源、可见内容和策略，不决定另一份精力或睡眠。

全局层保存经过授权、最小化的生活事实；每个流分别保存其社交上下文、对话缓存和注入去重记录。私聊约定可以影响全局忙闲时间，但其他群只看到“已有安排”，不能获得对方身份或约定全文。

发给模型的上下文必须限定来源及用途，不把所有群聊历史拼在一起。全局事件默认发布脱敏摘要；详细原因按授权查询。模型输出只能提出生活变更，不能获得修改身份、策略或直接发送消息的权限。

## 9. 持久化、恢复与历史

SQLite 为唯一主存储；缓存只是投影。数据分为状态快照、实际活动、计划与修订、睡眠会话与片段、目标、约定、偏好、习惯、生活事件和迁移审计。采用显式 Schema 版本迁移，失败停止切换，保留原数据。禁止“损坏则删库重建”。

重启按持久化 deadline 恢复任务，使用幂等键防止重复执行。停机期间只重建可由已提交计时规则确定的状态，不补写未经执行的学习、社交或模型决策。睡眠到期可记录为计划截止时确定性结束，同时标明 `recovered_after_downtime`、逻辑发生时间和实际记录时间；停机区间的细节保持未知。

近期保留详细记录，中期摘要，长期保留重要约定和事件。建议详细历史保留 30 天；R4 只有在摘要写入、覆盖范围和引用完整性验证后才清理。迁移原始记录、未完成约定、未投递事件、活跃活动和睡眠会话不随普通清理删除。与宿主记忆系统通过接口联动，不直接写宿主内部数据库。

## 10. 配置、可观察性与降级

普通配置围绕 `character`、`routine`、`planning`、`sleep`、`models`、`integration`、`admin`；高级参数围绕 `runtime`、`state`、`storage`、`observability`、`compatibility`。默认提供自然语言偏好，曲线、阈值和重试设置放高级区。

必须区分插件版本、配置版本、数据库 Schema 版本和事件/API 版本。新增自主模式使用 `planning.mode=autonomous`、`sleep.mode=autonomous`；`legacy_fixed` 只为 R0/R1 保持行为及受控过渡；`sleep.mode=disabled` 用于显式无睡眠配置，不得靠清空时间串表达。

必须可查询：当前主活动、睡眠阶段、下次到期时间、状态版本、最近决策原因、失败/降级状态、迁移状态和事件积压。调用日志记录任务、时延、预算、拒绝原因，不默认长期保存私聊全文、凭据或完整模型提示。

| 失败 | 行为 |
|---|---|
| LLM 超时/无效结构 | 保留状态；限次修正或延后；不强制入睡 |
| 状态版本过期 | 丢弃或重新排队；不能覆盖 |
| SQLite 写入失败 | 不发布成功事件、不更新缓存；暂停写入并报告 |
| 外部身份/策略不可用 | 拒绝特权写操作；基础计时与只读查询继续 |
| 社交消费者离线 | 生活继续；可靠事件积压受监测，过期社交机会不补发 |
| 新 Schema 无法读取 | 停止写入并指向恢复流程 |

## 11. 端到端验收场景

1. 两个群同时查询，得到同一活动/睡眠事实；私聊内容不泄露。
2. 23:30 偏好入睡，但 LLM 因合法原因推迟；程序不按偏好强制静默。真正入睡时有独立有效决策和时长。
3. 睡眠期间没有周期性模型调用；到期能醒，重启后也只产生一次醒来转换。
4. 学习途中疲劳增加，模型选择散步；计划差异和原因保存，已学一小时的历史保留。
5. 新计划与已确认约定冲突时被拒绝或产生明确改约提议，不静默挪动约定。
6. 模型返回非法时长、陈旧结果或越权命令，状态保持一致并可诊断。
7. 旧数据库含未来约定、跨午夜日程和未知行，迁移不丢失任何源记录；回滚恢复到已验证切换点。
8. 连续多日运行，有生活延续和合理变化；模型调用受预算约束，事件不产生主动发言风暴。

各场景的自动化编号、阶段归属和人工验收见开发计划。任何阶段不得用漂亮的生成文案替代状态、迁移和恢复正确性。
