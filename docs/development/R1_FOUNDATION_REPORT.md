## 实现摘要

| 任务 | 文件 | 已实现行为 |
|---|---|---|
| R1-01 时间 | `domain/clock.py` | Clock Protocol、SystemClock/ManualClock；显式 UTC 瞬时/毫秒/ISO 转换；IANA 本地日；DST 歧义必须指定 fold，不存在时间拒绝；墙钟跳变与单调时间分开 |
| R1-01 模型 | `domain/models.py` | LifeState、Activity、Plan/ScheduleItem/ScheduleRevision、SleepSession/Segment、Commitment、LifeEvent、LifeGoal/Preference；Habit/LifeSummary 仅预留领域形状，不建表/启动学习 |
| R1-01 约束 | `domain/constraints.py` | 单主活动、单开放睡眠会话、快照/实际记录一致、同角色引用、半开区间、历史不重叠、睡眠片段和时长缓存一致、版本/时间水位单调；临时中断不重置完整起床时间 |
| R1-02 Schema | `storage/migrations/001_initial.sql` | 新版 maivita.db Schema 1；17 张 R1 表、条件唯一索引、复合外键、严格类型/时间形状约束、历史保护与重叠触发器 |
| R1-02 迁移 | `storage/schema.py` | 显式事务迁移、版本/SQL SHA256、结构/索引/触发器校验、integrity_check 与 foreign_key_check；未知/高版本/篡改/漂移拒绝；迁移中失败完整回滚 |
| R1-02 仓储 | `storage/repositories.py` | 类型化读取/写入与 UTC 毫秒序列化，事件/修订只追加，状态仓储 expected_version 校验；所有写入绑定 Unit of Work，无独立提交 |
| R1-02 事务与快照 | `storage/life_database.py` | 显式新建与普通打开分离，禁止覆盖/隐式建库升级；外键/busy timeout/WAL；显式 commit、默认 rollback、捕获写入错误后仍禁止部分提交、跨表提交前校验；新库一致备份 |

插件发布版本仍为 0.1.0、配置仍为 1；新数据库 Schema 1 和事件格式 1 是独立版本空间。当前只交付初始迁移 001；后续结构变化应新增迁移，不能修改已投入使用数据库对应的旧迁移校验和。

模型里的计划、实际活动和历史事件不是同一份记录：日程睡眠项不会创建 SleepSession，时间经过不会将条目标为 done，日期级约定不被填成零点。冷启动 LifeState 的活动、完整起床、精力与睡眠债允许未知；fulfilled/done 要求显式完成依据。历史片段、事件正文和修订差异不可原地改写。

睡眠阶段与时间类型只是目标数据形状和合法性约束。没有实现选择何时睡、睡多久、窗口规划、自动切换活动、到期任务或唤醒命令；兼容睡眠没有提前套用 R2 的 1080 分钟等自主工程限制。

## 验证结果

环境沿用本地 Windows 11 / Python 3.13.6 / SDK 2.15.0；新增领域/存储基础无 SDK 依赖，单独禁用 SDK 导入的测试通过。全部数据库为自动清理的临时合成库，没有读取生产数据或真实聊天。

- 全套 **147 tests，0 failures / errors / skips**，含原 96 项 R0 回归与 51 项新增基础检查。结果：`evidence/r1-test-results.json`、`r1-test-results.txt`。
- pytest 复核 **147 passed、54 subtests passed**，无警告。
- T06 基础：真实 SQLite 拒绝双主活动/双开放会话、跨角色引用、历史重叠和不一致快照；两个并发写入者只提交一个主活动。
- T07 基础：中途异常、模拟 commit 磁盘写失败、捕获写入错误后尝试提交、迁移 DDL 中途失败均回滚；子进程在 commit 前/后 `os._exit`，重开两次仍只看到完整旧/新快照及单个事件。
- T08 仅仓储基础：expected_version、唯一键和状态单调校验通过；没有据此宣称命令 receipt 幂等、网络重送或 outbox 投递协议完成。
- T09 基础：UTC 毫秒、负 epoch、跨午夜、DST 23/25 小时日、重复/不存在时间及墙钟回拨通过；没有实施 R1-06 的运行恢复调度。
- 迁移保护：旧库、空但未初始化库、高版本、错误 checksum、缺失索引/历史触发器拒绝；失败升级保持原版本/原数据；重复应用同版本不重写历史时间。
- 新版库恢复演练通过，见 `evidence/r1-restore-drill.json`：活动 WAL 下复制已提交状态/事件，源 DB/WAL 哈希不变，恢复 SHA256 与快照一致、记录完整、未来版本被拒绝、`activated=false`。临时文件退出后清理。
