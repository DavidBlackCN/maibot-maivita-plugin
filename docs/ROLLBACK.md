# 回滚与恢复

1. 停止请求，禁用 MaiVita 或停止独立 Host；等待模型/worker/coordinator 与旧调度任务取消，共享 writer_lock 与 Runtime 锁释放。不能手工删除运行中的锁文件。
2. 保留当前库一致快照、authority、配置、事件水位和 T0 后约定/取消记录。switch_engine.py 在共享锁下为两种已有数据库保存校验过的一致快照，目标配置不会覆盖源配置。
3. 使用相同工具生成回切配置及新 revision 的票据，检查备份后显式重载。回切 legacy 仅恢复 legacy/goals.db 的旧数据语义，不将 life 的历史转换成旧计划；新库留存，不删记录，不自动重放社交事件。
4. 需要恢复某一数据库时，完全停机，将已校验快照恢复到新的空目录，核对 checksum、Schema、状态及事件数量，再在明确配置和切换记录下激活。不能把 maivita.db 改名 goals.db，不执行猜测性降级。
5. 若激活失败，插件自清理，不提交新的权威模式。先修复配置/票据或恢复匹配快照，不自动启动另一个引擎。已提交 authority 的切换必须使用新的反向票据，不能重放旧票据。

配置与数据库不是跨文件事务：切换票据是准备态，成功加载后 authority 原子替换为生效态。崩溃前后都只按匹配的配置和 revision 重新验证；不猜测、不双启。已发送消息和供应商模型调用不可回滚。

本轮只验证合成数据。生产迁移与真实业务回滚需要独立授权和新约定差异对账。
